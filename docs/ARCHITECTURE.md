# 架构说明

## 总览

当前版本是一个 PySide6 单进程桌面应用。PyInstaller 单文件 EXE 启动时可能出现启动器与实际应用两个同名进程，这不代表启动了两个桌宠实例；应用内部使用 `QLockFile` 阻止第二个正式实例。

```text
QApplication
  └─ PetController
      ├─ SaveData
      ├─ PetWindow
      │   ├─ 角色与神枪渲染
      │   ├─ 浮动神枪
      │   └─ 三种内嵌小游戏
      ├─ StatusPanel
      ├─ RestDialog（按需创建）
      ├─ WorldEndOverlay
      ├─ QSystemTrayIcon / QMenu
      └─ 心跳、移动、自动行为、定时保存定时器
```

## 启动流程

1. `main()` 检查 `--smoke-test`，必要时切换 Qt 离屏平台。
2. 创建 `QApplication`，设置程序名、版本和全身图标。
3. 使用 `QLockFile` 建立单实例锁。
4. 创建 `PetController`。
5. 控制器加载存档，创建窗口、托盘、菜单和定时器。
6. 恢复保存位置或放置到桌面右下角。
7. 进入 Qt 事件循环。

## 状态与存档

`SaveData.DEFAULT` 是存档结构的当前真源，主要分为：

- 身份与成长：名称、等级、经验、亲密度。
- 生理状态：饱食、精力、心情。
- 资源：饼干币、相位碎片。
- 视觉与行为：桌宠缩放、声音、自动散步、神枪显示和变换参数。
- 成长扩展：连续相伴、熟练度、游戏纪录、解锁、成就、计数器。
- 系统：最后在线时间和窗口位置。

存档位保存在 `%LOCALAPPDATA%\OthinusDesktopPet\save.json`。烟雾测试模式不会读取或写入正式存档。

现有兼容策略是用默认结构加载，再以保存值覆盖；嵌套字典只做一层 `update`。未来改变字段含义或删除字段前应增加 `save_schema_version` 与显式迁移器。

## PetWindow 渲染

窗口固定为 460×520 透明画布；角色基础绘制尺寸为 286，脚下锚点 Y=486。每张角色 PNG 在加载时通过 mask 计算真实 alpha 边界。

绘制顺序大致为：

1. 角色落地阴影。
2. 独立浮动神枪。
3. 上一个角色精灵和当前角色精灵的平滑过渡。
4. 神枪调整辅助线。
5. 粒子。
6. 内嵌小游戏或对话气泡。

神枪先于角色绘制，因此重叠时位于人物下层。独立神枪使用人物脚下锚点为原点的局部逻辑坐标，桌宠缩放时同比缩放，并将旋转后的完整矩形约束在透明画布内。

## 动作系统

`ACTION_VARIANTS` 将逻辑动作映射到一个或多个精灵文件；`ACTION_MIN_DURATIONS` 控制最短驻留时间。动作切换保留上一精灵，并在约 0.52 秒内平滑过渡。

逻辑动作包括待机、挥手、跳跃、摸头、生气、魔法、惊讶、进食、睡眠、哭泣、大笑、困惑、害羞、哈欠、无聊、赠礼、神枪待机、战斗、胜利、力竭、拖动、步行、边缘和世界终结。

## 移动状态所有权

窗口位置可能由三类行为改变：

- 人工拖动：`PetWindow` 持有鼠标起点和窗口起点。
- 自动散步：`PetController` 持有目标与浮点轨迹位置。
- 屏幕边缘吸附：控制器按照当前精灵真实轮廓计算目标位置。

v2.6.2 规定同一时刻只能有一种移动所有者：

- 人工按下即取消自动散步。
- 释放前先清除人工拖动态，再同步发出位置保存信号。
- 如果透明窗口漏收释放事件，发现左键已抬起后自动清理。
- “回到右下角”、隐藏和退出会清除全部拖动与散步状态。
- 自动散步每帧对比实际窗口位置与内部轨迹；出现外部位移时废弃旧目标。

任何后续移动修改都必须维护该互斥关系。

## 屏幕边缘

边缘检测使用角色真实可见轮廓，而不是 460×520 透明窗口。边缘行为在可见轮廓距屏幕 6 px 内触发；扶墙、探头等静态边缘动作可零间隙贴边，动态动作使用额外安全内缩。

切换精灵后会重新计算真实轮廓并重新锚定，避免不同帽子、披风、脚部和武器尺寸导致裁切或悬空。

## 内嵌小游戏

小游戏由 `PetWindow` 直接绘制和处理点击，不创建额外窗口：

- 北欧符文追迹：移动目标、伪符文、连击。
- 主神之枪校准：移动指针与共鸣区。
- 相位记忆：显示序列与玩家复写。

结束后通过 `inline_game_finished` 信号交给控制器结算经验、货币、熟练度、纪录和相位碎片。

## 全屏特效

`WorldEndOverlay` 是覆盖屏幕的独立透明窗口，分阶段绘制宣誓文字、魔法阵、空间收缩、碎片、星光回流与重构光柱。它只产生视觉效果，不操作系统文件。

## 素材流水线

`prepare_assets_v2.py` 读取 `assets_v2/` 的母图和图集，执行：

1. 网格动作完整轮廓提取。
2. 边缘碎片清理和主体保留。
3. 统一透明画布、比例与锚点。
4. 以 `idle_neutral` 为基准归一发色。
5. 处理睡姿、拖动、步行和边缘特殊图。
6. 生成独立神枪、世界演出图和全身图标。
7. 输出到 `assets/sprites_v2/` 和 `assets/`。

该脚本不是日常构建步骤。只有明确批准美术变更时才应运行。

## 构建与发布

`build.ps1` 当前会：

- 编译检查 `othinus_pet.py`。
- 使用 PyInstaller 构建窗口化单文件 EXE。
- 将整个 `assets/` 打包。
- 嵌入 `version_info.txt` 和全身 ICO。
- 排除未使用的 Qt WebEngine、Quick 与 QML 模块。
- 通知 Windows Explorer 刷新文件图标。

标准发布应在新版本目录构建，随后运行离屏验证和打包后烟雾测试，再复制 `README.txt`，最后才替换桌面 EXE。

## 模块化边界建议

后续可按以下顺序从单文件中提取：

1. `constants.py`：版本、动作映射、尺寸和安全边距。
2. `state.py`：SaveData 与迁移器。
3. `games.py`：三种小游戏状态与渲染辅助。
4. `effects.py`：WorldEndOverlay。
5. `dialogs.py`：RestDialog 与 StatusPanel。
6. `pet_window.py`：角色渲染与鼠标交互。
7. `controller.py`：业务协调。
8. `app.py`：main 与单实例启动。

不要一次完成全部拆分；每一步都应保持功能、资源路径和存档兼容，并运行完整回归。
